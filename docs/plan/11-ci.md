# 11 — CI (GitHub Actions)

**Parent:** [00-high-level.md](00-high-level.md) §11
**Milestone:** M0 (build/test matrix), M6 (publish hardening)
**Status:** Approved

## 1. Scope

GitHub Actions CI that builds, tests, and reports coverage on **both** target OS (Windows + Linux) for every push/PR. The platform matrix is the safety net for hardlink/statvfs/path behavior (`10` §6). No legacy CI to replace (v2 had none).

## 2. Workflow layout

```
.github/workflows/
├─ ci.yml               # build + test + coverage on windows-latest, ubuntu-latest
├─ build.yml            # reusable (workflow_call): build + test + per-OS publish & packaging
├─ package.yml          # manual (workflow_dispatch): dry run of build.yml — artifacts only
└─ release.yml          # tag push (v*): build.yml → GitHub Release with artifacts (M6)
```

## 3. `ci.yml` — matrix build & test

Triggers: `push` to `main`, `pull_request`.

```
matrix:
  os: [windows-latest, ubuntu-latest]

steps:
  1. actions/checkout@v4
  2. actions/setup-dotnet@v4   # dotnet-version: '10.0.x' (cache: true)
  3. dotnet restore LincleLINK.sln
  4. dotnet build LincleLINK.sln -c Release --no-restore   # build = verification
  5. dotnet test LincleLINK.sln -c Release --no-build
       --collect:"XPlat Code Coverage"
       --results-directory artifacts/coverage
  6. actions/upload-artifact@v4  # artifacts/coverage (cobertura) as PR artifact
```

Notes:

- **Headless-safe:** tests are logic/FS-based (`10`); neither CI OS launches the GUI, so no display/xvfb needed.
- Platform-conditional tests (`PlatformGuard`) run only on their host OS in the matrix — both paths get exercised.
- `setup-dotnet` cache speeds restore across runs.
- Pin action majors at M0 (current stable; adjust if newer majors are preferred).
- `ci.yml` failing on any OS blocks merge.

## 4. Coverage

- Collected via coverlet (`XPlat Code Coverage`, cobertura) per matrix OS; uploaded as an artifact.
- Target: ≥ 80% line coverage on Core `Domain`+`Application` (`10` D3).
- **Enforcement approach (D1):** start with the report + a documented target (soft), then harden at M6 to a failing check if the target is met sustainably. Hard-failing an unfinished suite at M0 would block progress.

## 5. `build.yml` / `package.yml` / `release.yml` — per-OS publish & packaging (M6)

`build.yml` is a reusable workflow (`workflow_call`) holding the shared pipeline: build + test once, then publish a **single-file, self-contained** executable per RID on its native runner and package it per platform. Callers:

- `package.yml` — manual `workflow_dispatch`; runs `build.yml` alone to test packaging (artifacts downloadable from the run, no release).
- `release.yml` — `push` on `v*` tags; runs `build.yml`, then creates a GitHub Release (auto-generated notes) with all artifacts attached. Keep `Directory.Build.props` `Version` in sync with the tag.

Pipeline details:

- `dotnet publish src/LincleLINK.App -c Release -r <rid> --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -p:EnableCompressionInSingleFile=true`
- RID matrix (native `runs-on`, `fail-fast: false`) and packaged artifacts:
  - `win-x64` on `windows-latest` → `LincleLINK-win-x64.exe` (bare executable)
  - `linux-x64` on `ubuntu-latest` → `LincleLINK-linux-x64.tar.gz` (executable + `.desktop` + icon from `packaging/linux/`)
  - `osx-x64` / `osx-arm64` on `macos-latest` → `LincleLINK-osx-{x64,arm64}.app.zip` (`.app` bundle via `packaging/macos/make-app-bundle.sh`, zipped with `ditto`)
- A follow-up `flatpak` job (needs `publish`) re-wraps the linux-x64 binary from the tarball artifact into `LincleLINK-linux-x64.flatpak` via `flatpak-builder` + `flatpak build-bundle` using `packaging/flatpak/io.github.radioo.LincleLINK.yml`. This is the recommended Linux install (Steam Deck: open with Discover): it installs the desktop file/icon so taskbar progress (Unity LauncherEntry matching) works without manual steps. The metainfo release version/date are stamped from `Directory.Build.props` at build time.

Notes:

- `IncludeNativeLibrariesForSelfExtract` is required so Avalonia's native Skia libs self-extract at runtime on Linux/macOS.
- `DebugType=None`/`DebugSymbols=false` drop PDBs from the publish output; PDBs are not part of the release.
- Self-contained avoids requiring the user to install the .NET runtime on any OS.
- Semi.Avalonia/DataGrid publish cleanly (no trimming needed; trimming out of scope).
- Icon/version metadata: `app.manifest` (Windows DPI) + `LL_logo.ico` carried into the App project (`01` §6).
- Publishing is M6 polish, not a prerequisite for feature work.

## 6. Decisions (locked)

- **D1** Coverage threshold is a soft target + report at M0; harden to a gate at M6.
- **D2** Release publish is single-file self-contained `win-x64` + `linux-x64` + `osx-x64` + `osx-arm64` (no PDBs), triggered by `v*` tags, with `package.yml` as a manual dry run; wired at M6.
